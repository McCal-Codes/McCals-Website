### Hooks and Commit Conventions Now Use the Standard Tooling

- `husky` and `lint-staged` were already declared in `package.json`, and `lint-staged` already had a real config running eslint and prettier over staged files. Neither ever ran: there was no `prepare` script and no `.husky` directory, so nothing invoked them.
- The hand-rolled `.githooks` directory they were meant to replace required every person to run `git config core.hooksPath .githooks` by hand. That was never done: the setting is unset in both checkouts, only sample hooks exist under `.git/hooks`, and none of the last sixty commits on `main` carries the `Author: mccal` note its `commit-msg` hook appends. So the migration loses nothing. `npm install` now wires the hooks through husky's `prepare` script, with no manual step.
- Its `post-commit` hook was deliberately not carried across. It ran the welcome script, which rewrites two tracked files after every commit; that churn then gets swept into the next `git add`. The dashboard is still available as `npm run welcome`.
- Conventional Commits are enforced with `@commitlint/config-conventional`. 44 of the last 60 commits already followed the format, so this records a habit rather than imposing one.
- **The check that matters runs on the pull request title, not on commits.** Merges here are squashes and the repository's `squash_merge_commit_title` is `COMMIT_OR_PR_TITLE`, confirmed through the API, so the title is the subject that lands on `main` and local commit messages are squashed away. `.husky/commit-msg` lints them anyway, for feedback where the message is written.
- The config was tuned against real history rather than guessed. Running it over the last sixty commits took the pass rate from 44 to 51, by turning off `subject-case`, which rejected this repository's sentence style such as "WebGL slide dissolve and per-breakpoint art direction", and by ignoring Dependabot, whose configured `deps-dev` prefix contains a hyphen that is not a valid Conventional Commits type character. Verified: `deps(scope): x` parses and `deps-dev(scope): x` does not.
- The nine still failing are all squash merges of pull requests titled as plain sentences, including one from earlier today. Those are the case this is meant to catch, so no ignore was added for them.
