### A Row Level Security Policy That Granted Nothing and Cost Something

- `portfolio_images`, `hero_slides` and `hero_slide_variants` each carried a `service_write` policy: `FOR ALL USING (auth.role() = 'service_role')`, with no `TO` clause. Without one it defaults to `TO public`, so it was evaluated on every anonymous `SELECT` alongside the `public_read` policy beside it, and `auth.role()` is `STABLE` rather than `IMMUTABLE`, so Postgres called it once per row instead of once per query.
- It also granted nothing. Checked against the database rather than assumed: `service_role` carries `rolbypassrls`, so it already reached these tables whatever the policy said. Anonymous and authenticated callers never satisfied the condition, so dropping it takes no access away from anyone.
- Supabase's own linter reported both problems independently, as `auth_rls_initplan` on all three tables and `multiple_permissive_policies` on all three. After the change `auth_rls_initplan` is gone entirely and `multiple_permissive_policies` is down from sixteen findings to one, an unrelated pair on `testimonials`.
- Timing was the reason to do it now rather than later. `portfolio_images` holds 422 rows, all journalism. Issue #280 would migrate the events portfolio, over 1,600 images, at which point every gallery read pays this per row across four paged requests.
- Verified before and after, at the database and through the public REST API with the key that ships in the browser bundle: anonymous reads return 422 rows and HTTP 200 on all three tables, an anonymous insert is refused with 401 and `42501`, no probe row was written, and `/`, `/journalism`, `/nature` and `/events` all return 200.
- One thing not done: an earlier note called `portfolio_images_portfolio_type_idx` a redundant prefix of the composite index and a candidate for removal. The linter no longer lists it as unused, so it has been used since that note was written. Left alone.
