# Repository Rules for Claude Code

This file contains repository-specific rules and guidelines for Claude Code to follow when working in this codebase.

## User Preferences

- **npm upgrades**: Do not upgrade global npm (`npm install -g npm@…`) unless there is a concrete need; ad hoc major bumps are a poor default.
- **Editor guidance**: Treat `.claude/rules.md` as the primary in-repo rules source for Claude Code.
- **URL conventions**: Use `/letting-me-go` as the canonical URL for the BFA thesis / "Letting Me Go" exhibition page on the public site.
- **Photo captions**: For on-site journalism and thesis photography, use AP-style photo captions and cutlines (datelines with abbreviated states, correct titles, consistent "Photo by" credit).
- **Punctuation**: Avoid em dashes in site copy (use commas, parentheses, or sentence breaks instead).
- **Citations**: For academic-style citations on the site, use APA author–date in text plus a References list; reserve footnotes for APA-allowed cases (e.g. explanatory notes, permissions).
- **Git hygiene**: Keep commits small/scoped, separate generated artifacts from logic/config unless intentional, avoid committing local noise (e.g. `.cursor/` and temp files) and AI-generated artifacts by default, run verification before each commit, and use intent-first commit messages (`security:`, `ci:`, `docs:`, `content:`).
- **Communication**: Ask clarification and scoping questions directly in chat instead of separate question dialogs.

## Workspace Structure

- **Active app**: The actively maintained public app for this monorepo lives under `sites/mcc-cal-vite` (Vite + React; lazy routes in `App.tsx`, SEO via `usePageMeta`).
- **CI / Vercel parity**: GitHub `vercel-deployment-checks.yml` runs `npm run build` (includes `tsc -b`), ESLint, `npm run ci:check`, `validate-manifests`, and Vitest `test:run`. Vercel project build command should stay aligned with `sites/mcc-cal-vite/vercel.json` (`npm run build`). Use `build:fast` only for intentional speed skips locally.
- **Dependencies**: Dependabot watches npm at repo root and at `sites/mcc-cal-vite`; review grouped dev-dependency PRs together.
- **Observability**: Production site uses Vercel Analytics and Speed Insights (`@vercel/analytics`, `@vercel/speed-insights`); expand only if you need deeper client error telemetry.
- **New routes**: New public routes should also be added to `sites/mcc-cal-vite/scripts/generate-sitemap.js` (`STATIC_ROUTES`) so they appear in the generated sitemap, alongside routing and nav updates.
- **Legacy content**: Legacy Squarespace-era widgets and related material are archived under `admin/_archived/`; CodeQL is configured to ignore that tree (see `.github/codeql/codeql-config.yml`).
- **Blog manifests**: Blog slugs used for listings and cross-links are driven by `src/content/blog/blog-manifest.json` at the repo root.
- **Journalism manifests**: The journalism portfolio manifest at `src/images/Portfolios/Journalism/journalism-manifest.json` is generated by `scripts/manifest/generate-journalism-manifest-v2.js` (e.g. `node scripts/manifest/generate-journalism-manifest-v2.js --force` from the repo root); after changing portfolio images or `tags.json`, sync into the Vite app with `node scripts/sync-manifests.js` in `sites/mcc-cal-vite`.
- **Project grouping**: Portfolio and thesis artwork pages are grouped under the Projects navigation area (including the BFA thesis / exhibition route).
- **BFA thesis images**: BFA thesis exhibition still images (not journalism albums) live under `sites/mcc-cal-vite/public-vite/images/bfa-thesis/`; served as `/images/bfa-thesis/...`. Journalism portfolio images stay only under `src/images/Portfolios/Journalism/` and manifests — no "Letting Me Go" in those paths.

## Development Workflow

1. **Before making changes**: Run `npm run build` in `sites/mcc-cal-vite` to verify the build passes.
2. **Type safety**: The project uses TypeScript with strict mode enabled. Always run `tsc -b` before committing.
3. **Testing**: Run `npm run test:run` in `sites/mcc-cal-vite` to execute the test suite.
4. **Linting**: Run `npm run lint` at the repo root to check code quality.
5. **Manifest sync**: After changing portfolio images or blog content, run `node scripts/sync-manifests.js` in `sites/mcc-cal-vite`.

## Code Style

- Use TypeScript for all new code
- Follow existing component patterns in `sites/mcc-cal-vite/src/components/`
- Use lazy loading for route components (see `App.tsx`)
- Prefer functional components with hooks
- Use CSS modules or scoped CSS for component styles
- Keep components focused and single-purpose

## Security

- Never commit `.env` files or API keys
- Use environment variables for sensitive configuration
- Review CSP headers in `vercel.json` before adding external domains
- Be cautious with `dangerouslySetInnerHTML` - only use for trusted content

## Performance

- Images should use WebP format where possible
- Add `loading="lazy"` to below-fold images
- Use `loading="eager"` and `fetchpriority="high"` for above-fold critical images
- Leverage code splitting for large components
- Review bundle size after adding new dependencies

## File Organization

- Keep generated artifacts out of version control (see `.gitignore`)
- Place utility functions in appropriate `utils/` directories
- Group related components in subdirectories
- Use descriptive file names that reflect purpose
